# 05 · 系统诊断手册

> 这里的「系统」指**运行环境**：解释器、路径、编码、磁盘、权限、文件系统。
> 不涉及内核、驱动、网络协议栈 —— 那些用操作系统自带工具更合适。

---

## 症状 1：磁盘满了 / 目录大得离谱

### 30 秒确认

```bat
ek fs D:\
```

或者先缩范围（全盘扫描会慢）：

```bat
ek fs D:\labdata --no-duplicates     :: 先跳过重复检测，只快扫
```

### 怎么判读

报告给出七个板块，按「离钱最近」的顺序看：

| 板块 | 回答什么问题 |
| --- | --- |
| 一、总体 | 多少文件、多大、多少零字节文件 |
| 二、空间分布（按扩展名） | 是 `.csv` 占满了，还是 `.png` 的中间结果占满了 |
| 三、最大的文件 | 具体的 TOP 10 |
| 四、零字节 / 疑似写失败 | 见下 |
| 五、重复内容 | 同一份数据存了 N 份 |
| 六、文件年龄 | 是旧数据堆着，还是刚刚生成了一堆 |
| 七、路径问题 | 见症状 5 |

### 零字节文件是最值钱的信号

```
[!!] FS020  有 3 个零字节文件
         → 建议=常见于磁盘写满、进程被 kill、网盘同步中断；对照修改时间定位事故窗口
```

上一次磁盘满导致写失败，会留下一个 0 字节的 `.csv`。它**不报错**，
直到你下次读它时才炸 —— 而这个「下次」可能是论文截止前一天。

看它们的修改时间：如果和你记忆中「程序莫名退出」的时刻吻合，那就是同一次事故。

### 重复内容怎么判定

先按**文件大小**分组（大小不同必然内容不同），再对同大小组算摘要：

- 小文件（≤16 MB）：全文 SHA-256
- 大文件：`头部 64KB + 尾部 64KB + 大小` 的指纹

第二种严格来说是「疑似重复」，理论上存在碰撞可能。报告里会显示「浪费空间」，
让你判断值不值得人工核对。

> 删之前确认哪一份是权威版本。**不要让工具替你删** —— 它连 `--delete` 都不提供。

## 症状 2：`PermissionError` / 文件读写不了

### 30 秒确认

```bat
ek env
```

看「问题判断」里这几条：

| 编号 | 含义 |
| --- | --- |
| `ENV008` | 当前工作目录不可写 |
| `ENV009` | 临时目录不可写 |
| `FS010` | 扫描时有多少目录读不进去 |
| `FS040` | 路径层面的问题（长路径、保留名…） |

工具的判定方式是**真的写一个临时文件再删掉**（`_is_writable`），
而不是查权限位 —— Windows 上权限位经常撒谎（继承的 ACL、只读属性、被占用的文件）。

### 常见的四种情况

**a) 文件被别的程序占用**

Windows 上最常见：Excel 打开着这个 CSV，Python 就以 `PermissionError` 写入失败。
`ek fs` 的「无法读取」列表能看到；写入失败只能靠关闭程序解决。

诊断时的表现很典型：

```python
df.to_csv("result.csv")   # PermissionError: [Errno 13] Permission denied
```

**b) 临时目录不可写 → 一堆莫名其妙的错**

`tempfile`、`matplotlib` 字体缓存、`pandas` 中间文件全都要写临时目录。
临时目录满了或被策略限制时，报错会出现在**完全不相干的地方**
（比如 `matplotlib` 报字体错误）。

```bat
ek env                        :: 看「ENV009 临时目录不可写」
echo %TEMP%                   :: 确认指向哪里
set TEMP=D:\temp && set TMP=D:\temp    :: 换个临时目录试试
```

**c) 路径太长**

Windows 传统路径上限 260 字符。超过之后某些 API 会失败而另一些成功，
导致「同样的代码有的文件能读有的不能」。

```bat
ek fs D:\project              :: 「七、路径问题」会列出所有超长路径
```

根治办法：把项目移到更浅的目录（`D:\lab` 而不是
`D:\Users\你\Documents\2024年项目\第三个子课题\实验数据\第二批\`）。

**d) 网络盘 / UNC 路径**

`\\server\share\...` 的权限、文件锁、速度都不可靠。`ek env` 会报 `ENV019`。
大文件操作失败时优先怀疑这里。

## 症状 3：明明装了包，却 import 不到

这是 Python 环境问题里最经典的一个。**几乎总是「装错解释器」。**

### 30 秒确认

```bat
ek env
```

看两节：

```
== PATH ==
| python 可执行文件数 | 3 |
| python[0]           | C:\Program Files\Python312\python.exe |
| python[1]           | C:\Users\你\anaconda3\python.exe |

== Python 解释器 ==
| 可执行文件 | C:\Users\你\anaconda3\python.exe |
```

**`python[0]` 和「当前运行的可执行文件」不是同一个** → 就是这个原因。
`pip install` 装进了 `python[0]`（PATH 里第一个），但你现在跑的是另一个。

### 三种解法

```bat
:: a) 用同一个解释器装和跑（最稳）
C:\Users\你\anaconda3\python.exe -m pip install 包名
C:\Users\你\anaconda3\python.exe -m ekits code .

:: b) 确认当前解释器的 site-packages 在哪
python -c "import sys; print(sys.path)"

:: c) conda 用户
conda activate 环境名
python -m pip install 包名
```

### 其他「装了却找不到」的原因

| 编号 | 原因 | 判断 |
| --- | --- | --- |
| `ENV012` | 项目里有同名 `.py` 覆盖了包 | 报错「本地文件与标准库同名」 |
| `ENV013` | `sys.path` 含当前目录，优先级最高 | 在数据目录里跑脚本时尤其容易 |
| `ENV002` | `PYTHONPATH` 指向不存在的目录 | 直接打印出来 |
| `ENV001` | 设置了 `PYTHONHOME` | 会让解释器找错整个类库目录 |

> `PYTHONHOME` 是最毒的一个。它一旦被设成错误的值，`import` 会从完全错误的地方
> 找库，症状是「什么都 import 不了，但 pip 说都装好了」。断网排查时**先撤销它**：
> `set PYTHONHOME=`（Windows）或 `unset PYTHONHOME`（bash）。

## 症状 4：程序卡住 / 网络请求一直转圈

断网环境下的典型陷阱：**代理**。

程序不是快速失败，而是**等超时**（默认可能几分钟）。表现就是「卡住了」。

### 30 秒确认

```bat
ek env
```

看「相关环境变量」里有没有 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`：

```
[!!] ENV004  设置了代理变量 ['HTTP_PROXY', 'HTTPS_PROXY']。
         断网环境下任何走代理的请求都会长时间卡住（表现像「程序假死」），而不是快速失败。
```

### 处理

```bat
set HTTP_PROXY=
set HTTPS_PROXY=
set ALL_PROXY=
:: 或者显式排除本地
set NO_PROXY=localhost,127.0.0.1
```

顺便：`ek env` 也检查 `pip` 是否可用（`ENV005`）。断网时 pip 不可用意味着
「不要指望装东西」，这个事实比任何报错都重要。

## 症状 5：文件名诡异 / 删不掉 / 打不开

```bat
ek fs D:\labdata
```

「七、路径问题」会列出六类：

| 类型 | 为什么麻烦 |
| --- | --- |
| 名字以空格或点结尾 | Windows 上能创建出来，但删除/重命名会被拒绝 |
| `CON` / `PRN` / `AUX` / `COM1`… | 设备保留名，某些 API 直接拒绝访问 |
| 含 `<>:"|?*` | 非 Windows 创建的文件带过来的 |
| 路径过长（>259 字符） | 部分工具读写失败 |
| 坏软链接 | 指向的目标已不存在 |
| 大小写仅不同的同名文件 | Windows 不区分大小写，两个文件会互相覆盖 |

### 删不掉的修法

```bat
:: 用 \\?\ 前缀绕过路径长度限制
del "\\?\D:\very\long\path\file.csv"

:: 或者先改名再删
ren "带空格的名字 " "临时名"
del "临时名"
```

## 症状 6：日志里看不出任何有用信息

```bat
ek log app.log
```

如果日志本身就有问题，先修日志再看内容：

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| `LOG002` | 解码出现替换字符 | 中文全变 `?`，等于没日志 |
| `LOG003` | 疑似乱码 | 编码错了 |
| `LOG001` | 行尾混用 | `grep` / `diff` 出现幽灵差异 |
| `LOG004` | 含 NUL 字节 | 可能不是文本日志 |

### 错误签名聚类怎么用

```
| 次数 | 占比(错误) | 典型内容                                            |
|   35 |    100.0%  | 2024-03-01 00:01:59 ERROR 批次 1006 处理失败: KeyError('value') |
```

35 条错误聚成 1 类 → 说明是**同一个**故障在重试，修一处即可。
如果聚成 12 类，那才是多个独立问题。

聚类方式：把数字、路径、UUID、IP、时间戳替换成 `<n>` / `<path>` / `<uuid>` / `<ip>`
/ `<ts>` 这些占位符，然后按结果分组。这是个老办法，但比任何索引都好用。

### 危险关键词

日志里出现这些词时会被单独列出来：

```
traceback (most recent call last)  ·  out of memory  ·  no space left
segmentation fault  ·  permission denied  ·  connection refused
killed  ·  core dumped  ·  corrupt  ·  checksum mismatch
```

## 症状 7：出图时中文变方块

这是**字体**问题，不是编码问题。`ek` 会自动挑中文字体（微软雅黑 / SimHei /
Noto Sans CJK / 文泉驿…），一个都找不到时会明确告警：

```
[!!] PLOT010  没找到可用的中文字体，图里的中文会显示成方块
         → 建议=安装 SimHei / 微软雅黑 / Noto Sans CJK 任一款，或把 --title 换成英文
```

顺便：`ek plot` 强制 `Agg` 后端，**永远不弹窗**。因为急救现场常是 SSH 或远程桌面，
`plt.show()` 会直接卡死。图永远写到文件里，你自己决定什么时候打开。

如果连 matplotlib 都没有，`ts` 和 `anomaly` 的**文本 sparkline** 仍然能看形状：

```
▂▂▂▂▂▂▂▂▂█▄▅▁▂▄▅▂▂▃▃▁▂▁▄▁▅▂▁▁▅▄▁▃▂▄▄▃▆▃▄▃▅▂█▂▅▂▄▃▃▅▁▄▄▃▂▃▁▄▅▅▅▇▇▇▇▅▂▄▆▂▃▄▃▆▅▅▃▄▅
```

（这段里能看出一个平台区 `▇▇▇▇` = 传感器卡死，和两个尖峰 `█`）

## 快速对照表

| 症状 | 命令 | 关键结论 |
| --- | --- | --- |
| 磁盘满 | `ek fs <目录>` | 零字节文件、重复浪费、按扩展名分布 |
| 读写不了 | `ek env` | `ENV008`/`ENV009`（真实写测试）、`FS010` |
| import 不到 | `ek env` + `ek code` | `ENV007`（多个 python）、`ENV012`（遮蔽）、`CS120`（缺依赖） |
| 卡住 / 超时 | `ek env` | `ENV004`（代理变量） |
| 中文乱码 | `ek encoding` | 推断编码 + 把握程度 |
| 出图方块 | `ek plot` | `PLOT010`（无中文字体） |
| 文件删不掉 | `ek fs` | 长路径 / 保留名 / 末尾空格 |
| 日志没信息 | `ek log` | 签名聚类、危险关键词 |
