# 01 · 工具清单与决策树

## 第一部分：先看哪里，再看什么

急救时最贵的成本不是算力，是**注意力**。所以先按「问题出现在哪一层」分流：

```
出问题了
│
├─ 数据不对（结果和预期不符、行数变了、指标飘了）
│   │
│   ├─ 完全不知道这个文件是什么 ──────────── ek triage  <文件>
│   │
│   ├─ 想知道「这份数据能不能用」 ────────── ek quality  <文件>   ← 结论
│   │                                    ek profile  <文件>   ← 事实
│   │
│   ├─ 怀疑某些数值点错了 ──────────────── ek anomaly  <文件> --column <列>
│   │
│   └─ 是时间序列（有采样时间） ──────────── ek ts       <文件> --time <列> --value <列>
│
├─ 代码不对（报错、昨天能跑今天不行、结果不可信）
│   ├─ 有报错信息 ──────────────────────── ek code     <路径>   ← 语法/反模式/依赖
│   └─ 怀疑环境变了 ─────────────────────── ek env                ← 解释器/PATH/编码
│
├─ 系统不对（磁盘、权限、卡顿、找不到文件）
│   ├─ 目录/空间/文件层面 ───────────────── ek fs       <目录>
│   └─ 运行环境层面 ─────────────────────── ek env
│
└─ 怀疑工具本身坏了 ──────────────────────── ek selftest
```

## 第二部分：命令详解

### `triage` —— 应急第一条命令

自动判断目标是数据 / 日志 / 代码 / notebook / 二进制，然后**只跑相关的检查**，
最后给出一节「处置建议」，把命中的规则编号翻译成具体动作。

```
ek triage <路径>
  --files 3         目录模式下逐个分析的样本文件数（默认 3，优先大文件）
  --key <列名>      主键检查
  --limit 25        每类结论最多展示几条
  --max-rows        单个文件最多读多少行
```

**什么时候不用它**：已经知道具体问题（比如就是怀疑某个数值列的尖峰），
直接用 `anomaly` 更快、结论更细。

### `profile` —— 结构速览（事实层）

```
ek profile <文件> [<文件2> ...]
  --columns a,b     只看这些列
  --head 5          展示前几行（0 = 不展示）
  --max-columns 40  最多展示多少列
  --hist            对第一个数值列画文本直方图
  --delimiter       显式指定分隔符（默认自动嗅探）
  --encoding        显式指定编码（默认自动探测）
```

输出的列画像是「一份数据的基本体征」：

| 列 | 说明 |
| --- | --- |
| 类型 | 整数 / 浮点 / 布尔 / 日期时间 / 日期 / 文本 / 空 |
| 非空 | 真正有值的行数 |
| 缺失 | 确定缺失的百分比（`NA`、空串、`null`、`缺失` 等） |
| 唯一值 | 去重后的取值个数；`+` 表示超出统计上限 |
| 取值范围 | 数值给 min~max；时间给起止；文本给长度区间 |
| 中位/示例 | 数值给中位数（对偏态比均值可靠）；文本给第一个样例 |

### `quality` —— 数据体检（结论层）

```
ek quality <文件>
  --key <列名>          主键：检查唯一性和空值
  --missing-warn 0.05   缺失率超过 5% 报「警告」
  --missing-error 0.5   缺失率超过 50% 报「严重」
  --limit 40            最多展示多少条结论
```

规则分三档严重程度：`严重`（数据已经不可用）、`警告`（能跑但结论不可信）、
`提示`（值得知道但不必改）。

### `anomaly` —— 异常点扫描

```
ek anomaly <文件>
  --column <列名>        要分析的数值列（默认第一个数值列）
  --methods z,modz,iqr,jump,roll,cusum   方法列表
  --threshold 3.0        z 类判断阈值
  --iqr-k 1.5            IQR 倍数（3.0 = 极端）
  --window 20            滚动窗口大小
  --all                  扫描所有数值列，只给汇总
  --plot 图.png          同时出图
```

六种方法各自的假设与失效条件：

| 方法 | 抓什么 | 什么时候会骗你 |
| --- | --- | --- |
| `z` z-score | 明显偏离均值的点 | 数据不近似正态、或异常点本身把标准差拉大（掩蔽效应） |
| `modz` 修正 z | 同上，但对掩蔽稳健 | 中位数附近一半以上取值完全相同时需要降级处理（已实现） |
| `iqr` 四分位距 | 偏态分布下的离群值 | 离散取值的列（如评分 1~5）会误报 |
| `jump` 跳变 | 某一刻突然变成另一个量级 | 对缓慢漂移不敏感 |
| `roll` 滚动 z | 流式/在线场景的突刺 | 漂移会污染基准窗口 |
| `cusum` 累积和 | 均值持续偏移的**起点** | 需要足够长的数据（≥20 点） |

**判读要点**：报告按「票数」排序。票数 ≥2 的点值得马上看原始记录；
只被一种方法命中的点，多半是该方法本身的偏好。

### `ts` —— 时间序列诊断

```
ek ts <文件> --time <时间列> --value <数值列>
  --gap-factor 1.5             间隔超过中位数的几倍算断档
  --flat-min 5                 连续多少个相同值算「卡死」
  --regularity-tolerance 0.1   判定「规整」的偏差比例
  --plot 图.png
```

检查项：采样间隔（中位数 + 规整度 + 常见间隔分布）、断档（位置 + 估计缺失点数）、
重复时间戳、时间倒序、覆盖率（实际点数 / 理论点数）、平直段（传感器卡死）、
线性趋势与 R²、前后半段均值漂移、自相关峰值（疑似周期）。

### `plot` —— 出图

```
ek plot <文件> --kind series|hist|missing --column <列> --plot-out 图.png
```

强制使用 `Agg` 后端（无界面），只写文件、永不弹窗 —— 因为急救现场常常是 SSH
或没有 X server 的机器，`plt.show()` 会直接卡死。

图中中文会自动挑系统字体（微软雅黑 / SimHei / Noto CJK / 文泉驿…）。
一个都找不到时会在报告里警告「图中中文会显示成方块」，而不是默默画出一堆豆腐块。

### `log` —— 日志诊断

```
ek log <文件> --top 12 [--grep 正则] [--encoding gb18030]
```

核心是**错误签名聚类**：把数字、路径、UUID、IP、时间戳归一化成占位符，
于是 35 条「批次 1006 处理失败 / 批次 1007 处理失败 …」会合并成一行 `×35`。
这比逐条翻阅快一个数量级。

同时给出：级别分布、时间范围、异常类型统计、危险关键词命中
（`traceback`/`out of memory`/`no space left`/`segmentation fault`…）。

### `encoding` —— 编码与文本体检

```
ek encoding <文件> [--hex] [--convert utf-8 --to 新文件.csv | --inplace]
```

编码探测会给出**结论 + 判断依据 + 把握程度**，而不是只甩一个编码名：

```
推断编码     gb18030
判断依据     候选编码打分最高
把握程度     medium
```

`medium` 意味着 GBK / Big5 / Shift-JIS 之间存在歧义（它们共享大量双字节范围），
必须抽查前几行中文确认。转码与读文件用**同一份**解码结果，不会出现「看完报告再转
一遍又猜错了」的情况。

### `env` —— 环境快照与问题判断

```
ek env [--root 目录] [--no-git]
```

七个板块：Python 解释器、平台、编码与区域、可选依赖、解释器搜索路径、PATH、
磁盘与内存、相关环境变量、版本库状态，最后是**问题判断**。

判断的都是「能解释玄学故障」的那类事实：

| 编号 | 检查 |
| --- | --- |
| `ENV001` | 设置了 `PYTHONHOME`（最毒的一个变量，会让 import 随机失败） |
| `ENV006` | 标准输出编码不是 UTF-8（输出中文会抛异常） |
| `ENV007` | PATH 里有多个 python（「装了却 import 不到」的元凶） |
| `ENV008` / `ENV009` | 工作目录 / 临时目录不可写 |
| `ENV010` / `ENV011` | 磁盘剩余空间不足 |
| `ENV012` | 本地文件覆盖了标准库同名模块（如项目里有个 `json.py`） |
| `ENV015` | 运行在 `-O` 模式（`assert` 被整段删除） |
| `ENV019` | 工作目录在网络路径上（文件锁/速度都不可靠） |

### `fs` —— 目录体检

```
ek fs <目录> [--max-files 200000] [--top 10] [--no-duplicates]
```

空间分布（按扩展名）、最大的文件、零字节文件（写失败的典型症状）、
重复内容（按大小 + 摘要判定，不是靠文件名）、文件年龄分布、
路径问题（Windows 长路径 / 保留名 / 末尾空格 / 坏软链接 / 大小写冲突）。

### `code` —— 代码静态体检

```
ek code <路径> [--limit 60] [--no-imports] [--no-notebooks]
```

四类检查：**能不能跑**（语法、依赖可用性）、**会不会静默出错**（裸 except、
吞异常、`open` 缺 `encoding`）、**换环境就坏**（硬编码路径、已移除 API、网络调用）、
**notebook 特有**（执行顺序乱、存着报错输出、kernel 版本不一致）。

详见 [04-代码诊断手册](04-代码诊断手册.md)。

### `selftest` / `demo`

```bat
ek selftest          :: 11 项核心逻辑自检，10 秒内出结果
ek demo              :: 在 samples\ 下生成 6 个「带病」文件
```

## 第三部分：规则编号索引

每条结论都有固定编号，方便在笔记、工单、复盘里引用：「上次是 `DQ161` 主键重复
导致 merge 行数翻倍」。

| 前缀 | 所属模块 | 范围 | 含义 |
| --- | --- | --- | --- |
| `DQ0xx` | quality（原始文件） | `DQ001`–`DQ018` | 空文件、BOM、行尾、NUL、替换字符、超长行 |
| `DQ1xx` | quality（表格内容） | `DQ101`–`DQ163` | 空列、常量列、缺失率、脏值、哨兵值、时间重复、重复行、主键 |
| `PROF` | profile | `PROF000`–`PROF001` | 列画像附注（ID 疑似、常量列…） |
| `ANOM` | anomaly | `ANOM000`–`ANOM005` | 异常扫描的执行状态与参数问题 |
| `TS1xx` | ts | `TS001`–`TS150` | 找不到列、重复时间、断档、卡死、趋势、周期 |
| `LOG0xx` | log | `LOG001`–`LOG030` | 行尾混用、替换字符、错误数量、签名聚类、grep |
| `ENC0xx` | encoding | `ENC001`–`ENC022` | 编码把握、行尾、二进制、转码 |
| `ENV0xx` | env | `ENV001`–`ENV019` | 见上表 |
| `FS0xx` | fs | `FS001`–`FS042` | 空间、零字节、重复、路径问题 |
| `CS0xx` | code | `CS001`–`CS130` | 语法、反模式、已移除 API、依赖、TODO |
| `NB0xx` | code（notebook） | `NB001`–`NB006` | 解析失败、报错输出、执行顺序、kernel 版本 |
| `TRI0xx` | triage | `TRI001`–`TRI200` | 分诊各环节与处置建议 |
| `PLOT0xx` | plot | `PLOT000`–`PLOT010` | 出图状态与中文字体 |

完整清单可以用 `--json` 导出后按 `findings[].code` 检索。

## 第四部分：串联与自动化

退出码专为 shell 串联设计（详见 [02-设计说明](02-设计说明与约定.md#退出码)）：

```bat
:: 数据有问题就停下来，不进入下一步
ek.cmd quality data.csv && python train.py

:: 只关心严重问题（不把警告当失败）
ek.cmd quality data.csv
if errorlevel 3 goto :tool_error
if errorlevel 2 goto :data_broken
```

批量跑一批文件并存档：

```bat
for %f in (D:\labdata\*.csv) do ek.cmd quality "%f" --json --out "D:\reports\%~nf.json" -q
```

用 Python 直接调用内核（不需要 subprocess）：

```python
from ekits import loader, profile, quality

table = loader.read_table("data.csv")
for issue in quality.check_table(table, key="id"):
    print(issue.level, issue.code, issue.title)
```

所有 `ekits` 模块都是纯函数式接口（输入数据 → 返回结构体），
不依赖命令行层，可以单独 import 使用。
