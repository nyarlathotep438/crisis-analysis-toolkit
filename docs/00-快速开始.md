# 00 · 快速开始

> 目标：从「拿到这套东西」到「成功跑出第一份报告」不超过 5 分钟。

## 1. 前置检查

只需要 Python 3.9 或更高版本（开发与验证环境是 3.13.5）。**不需要安装任何第三方包。**

```bat
python --version
```

如果提示找不到 `python`，说明它不在 PATH 里。三个办法任选：

1. 用完整路径：`C:\Users\你\anaconda3\python.exe -m ekits triage 数据.csv`
2. 在「开始菜单」搜 Anaconda Prompt，用那个终端（它自带 PATH）
3. 临时加进当前终端：`set PATH=C:\Users\你\anaconda3;%PATH%`

> **如果你的机器上装了多个 Python**，请先跑 `ek env` 看「PATH」那一节：它会列出
> 所有 `python.exe` 和当前实际使用的那个。装错环境是「明明 pip install 了却 import
> 不到」的头号原因，这个检查比什么都快。

## 2. 三种调用方式（完全等价）

| 方式 | 命令 | 适合 |
| --- | --- | --- |
| 启动器 | `ek.cmd triage data.csv` | 日常最省事；自动处理好导入路径 |
| 包入口 | `python -m ekits triage data.csv` | 在任意目录都能用，不依赖 `ek.cmd` |
| 独立脚本 | `python scripts/triage.py data.csv` | 想把某个脚本单独拷走时 |

三者跑的是同一份代码。`scripts/` 下的每个文件都是一层薄壳，只做一件事：
把自己的参数转交给 `ekits.cli` 里对应的子命令。

## 3. 第一次运行：先自检

> 注意：如果你使用的是PowerShell运行该命令，会被安全拦截，你需要在进入仓库后运行`.\ek.cmd`，其余操作也是如此，需要使用路径指定。

```bat
ek.cmd selftest
```

期望看到 11 项全部「通过」。它在 10 秒内验证格式化、表格对齐、编码探测、列画像、
质量规则、异常检测、时序诊断、代码体检、CSV 往返、报告导出、依赖探测这些核心逻辑。

**如果自检就失败了**，说明是工具箱本身的问题（复制过程中文件被截断、Python 版本太老），
不是你的数据的问题 —— 这时候不要急着分析数据，先换一台机器或用原始压缩包重新解压。

## 4. 第二次运行：用演练数据熟悉工具

真实的急救现场不适合用来学工具。因此你可以先生成一批**刻意带病**的数据：

```bat
ek.cmd demo
```

它会在 `samples\` 下生成 6 个文件，每个都埋了特定的坑（时间空洞、传感器卡死、
GBK 编码、分号分隔、重复列名、日志里反复报错、代码里的经典反模式…… 完整清单见
`samples\README.txt`）。

然后一条命令看全貌：

```bat
ek.cmd triage samples
```

你会看到：目录概况 → 每个数据文件的质量结论 → 数值列异常扫描 → 时间轴健康度 →
日志错误聚类 → 代码问题 → 最后的「处置建议」。

> **演练的意义**：等真出事的时候，你已经知道正常输出长什么样。
> 报告里该出现「2 处断档」而只出现 0 处，你立刻能判断是数据变干净了还是工具失灵了。

## 5. 面对真实数据：三条命令的取舍

**情况 A：完全不知道这个文件是什么**

```bat
ek.cmd triage 某个文件
```

它会自己判断是表格、日志、代码还是 notebook，然后只跑相关的检查。

**情况 B：知道是数据，但不知道有没有问题**

```bat
ek.cmd quality 数据.csv
ek.cmd profile 数据.csv --hist
```

`quality` 给结论（哪条规则被触发），`profile` 给事实（每列的类型、缺失、分位数、分布形状）。
先看结论能省时间，再回来看事实能解释原因。

**情况 C：怀疑某个数值列有脏点**

```bat
ek.cmd anomaly 数据.csv --column 列名
```

六种方法各自算一遍并投票。**票数 ≥2 的点优先人工核对**；只被一种方法命中的点，
多半是那个方法本身的偏好（例如 z-score 在重尾分布上误报很多）。

## 6. 常见问题

### 终端里中文变成乱码 / 报 UnicodeEncodeError

Windows 控制台默认编码常常不是 UTF-8。三种处理：

```bat
chcp 65001                          :: 当前终端切成 UTF-8
set PYTHONIOENCODING=utf-8          :: 让 Python 强制用 UTF-8 输出
ek.cmd triage data.csv --out r.md   :: 干脆存成 UTF-8 文件再打开
```

工具箱本身对这些情况做了兜底（输出流设成 `errors="replace"`、表格边框只用 ASCII、
sparkline 检测不到方块字符就自动降级成 ASCII 渐变），所以**不会崩**，但可能丢字形。
要完整显示中文，`chcp 65001` 最直接。

### 报告太长，看不完

```bat
ek.cmd triage data.csv --out 报告.md
ek.cmd triage data.csv --json --out 报告.json
```

`--out` 按后缀自动选格式：`.md` 适合贴进笔记、`.json` 适合脚本再处理、其他按纯文本。
终端输出和文件内容**同源**，不会出现两处结论不一致。

`--limit 10` 控制每类结论最多显示几条，`-q` 只写文件不打印。

### 想把这些报告留档

建议按 `日期_对象_命令.md` 命名，例如 `2024-03-01_sensor_csv_quality.md`。
急救报告的价值在事后复盘：同一份数据「修好前/修好后」各跑一遍，对比结论差异，
比任何日志都能说明问题。
