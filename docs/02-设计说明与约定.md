# 02 · 设计说明与约定

这份文档解释「为什么是这个样子」。如果你想改工具箱、或者想知道它的结论什么时候
不该相信，先读这里。

## 1. 零依赖内核 + 可选增强

**核心决策：主路径只用标准库。**

一台断了网的机器，最可能的状态是：`pip install` 用不了、conda 源连不上、
某个包版本冲突导致 import 崩掉。这时候一个「需要 pandas 才能运行」的诊断工具
是**在最需要它的时候失效**。

所以每个模块都遵循同一条模式：

```python
# 例：profile.py 里的数值解析
def parse_float(value):
    ...纯 Python 实现...
```

```python
# 例：loader.py 里只有标准库真做不到的地方才用 pandas
if suffix in (".xlsx", ".parquet"):
    pandas = deps.optional("pandas")
    if pandas is None:
        raise UnsupportedFormat("读 xlsx 需要 pandas，断网时可选的替代方案：…")
```

`deps.py` 是唯一允许 import 第三方库的地方，而且**任何异常都算「不可用」**
（包括 `OSError`、DLL 加载失败 —— 它们比单纯的 `ImportError` 更常见）：

```python
def _load(name):
    try:
        module = importlib.import_module(name)
    except Exception:
        module = None        # 损坏的安装不算可用
    return module
```

代价是：纯 Python 的数值计算比 numpy 慢。在 20 万行以内这没有实际影响
（实测整表画像 30 ms 级），超过 20 万行请用 `--max-rows` 控制，而不是指望它变成 pandas。

## 2. 只读默认

**核心决策：诊断工具绝不「顺手帮你修好」。**

急救最怕的不是发现问题，而是破坏了现场 —— 你再也无法回答「修之前是什么样」。
所以：

| 操作 | 默认 | 必须显式指定 |
| --- | --- | --- |
| 读文件 | ✅ 允许 | — |
| 写报告 | ❌ 不写 | `--out 文件` |
| 出图 | ❌ 不出 | `--plot 图.png` / `--plot-out` |
| 转码 | ❌ 不转 | `--convert 编码` + `--to 新文件`（或 `--inplace`，会先备份 `.bak`） |

唯一会自动写文件的地方是 `ek demo`（生成演练数据到 `samples\`）和 `selftest`
（在系统临时目录里做一次 CSV 往返，用完即删）。

## 3. 报告单一来源

终端输出、`--json`、`--out 报告.md` 三者由**同一个 `Report` 对象**渲染：

```
Report._blocks: [(section, ...), (finding, ...), (table, ...), (text, ...)]
                 │
      ┌──────────┼──────────┐
   render()  render_markdown()  to_dict() → json
```

好处是不会出现「屏幕上说 3 个问题、导出文件里说 2 个」。代价是三种格式都要维护，
所以 `report.py` 刻意保持很薄 —— 只有四种 block 类型。

数据结构：

```python
@dataclass
class Finding:
    level: str      # ok / info / warn / error
    code: str       # DQ104 这样的规则编号
    message: str    # 一句人话结论
    detail: dict    # 证据（数值、样例、路径）
    where: str      # 位置（file:line）
```

`level` 三档 + `ok`：
`error` 数据已不可用 → `warn` 能用但不可信 → `info` 值得知道 → `ok` 明确正常。

**为什么要有 `ok` 级？** 因为「我检查了而且没问题」和「我没检查」是完全不同的信息。
一份报告全是 `warn` 和一份报告全是 `ok`，处理方式截然相反。

## 4. 中文终端的三个具体问题

### 4.1 宽度对齐

`len("数据")` 是 2，但它在等宽终端里占 4 列。用 `len` 算宽度，纯中文表格会整体错位。

```python
def _char_width(char):
    if unicodedata.combining(char):
        return 0
    if unicodedata.east_asian_width(char) in ("W", "F"):
        return 2
    return 1
```

所有对齐、截断、表格边框都走 `display_width()`，不用 `len()`。

### 4.2 边框只用 ASCII

画框字符 `│ ┼ ─` 在 cp936 / cp437 控制台下**无法编码**。当输出被重定向到文件时，
Python 会用 locale 编码（中文 Windows 上是 cp936），此时 `print("│")` 直接抛
`UnicodeEncodeError` —— 报告在最后一步崩掉，前功尽弃。

所以表格边框固定用 `+ - |`。

### 4.3 sparkline 自动降级

文本折线用 `▁▂▃▄▅▆▇█`（U+2581–U+2588），这些字符在不同终端下宽度和字形都不稳定。
所以运行时会先探测能否编码：

```python
def _ramp():
    return _RAMP_UNICODE if _can_encode(_RAMP_UNICODE) else _RAMP_ASCII  # " .:-=+*#%@"
```

另外 stdout 在 `cli.main()` 开头统一 `reconfigure(errors="replace")`：
万一是别的编码，字符会变成 `?` 而**不会崩**。

## 5. 数据判读的几个约定

### 5.1 缺失值分两档

```python
MISSING_TOKENS  = {"", "na", "n/a", "nan", "null", "none", "nil", "无", "空", "缺失", ...}
SUSPECT_TOKENS  = {"-", "--", "?", "unknown", "未知", "不详", ...}
```

前者是**确定缺失**（`NA` 不可能是合法数据），后者是**疑似缺失**
（`-` 也可能真就是负号，`?` 也可能就是问号）。

分开统计的理由：`-999` 这类哨兵值混进均值计算，会把 50 的均值算成 -20，
而且**不会有任何报错**。这一类静默污染是最难查的数据事故。

### 5.2 类型推断用 95% 规则

```python
if as_int / total >= 0.95:
    return "int"
```

为什么不是 100%？因为现实的 CSV 里总有几个脏值。如果要求 100%，
一个错字就能让整列退化成「文本」，于是所有数值检查全部静默跳过 ——
**这比报错更危险**。

代价是必须把剩下的 5% 单独报出来（规则 `DQ115` 数值列含脏值），
并且这些值被**排除在统计之外**（报告里会写明）。

### 5.3 时间解析不接受 8 位纯数字

`20240101` 既可能是日期也可能是 ID。所以：

```python
if not any(sep in text for sep in ("-", "/", ".", ":", "T", "年")):
    return None      # 没有分隔符，不当日期
```

`20240101` 会被当成整数，`2024-01-01` 才是日期。宁可漏判也不要误判 ——
把 ID 当日期会让时序诊断得出一堆荒谬的结论。

### 5.4 IQR 退化为 0 时的降级

当一半以上的取值完全相同时（例如 30 个点里 29 个是 `10.0`），
`Q1 = Q3 = 10.0`，`IQR = 0`，Tukey 规则在数学上失效 —— 任何不同值都「超出零宽的箱体」。

处理方式是**有条件降级**：

- 与中位数不同的点 ≤ 10% → 改用平均绝对偏差重新划界，并在说明里注明「IQR 为 0，已降级」；
- 超过 10% → 直接返回空。这说明这是离散取值（如评分 1~5），不是异常。

不降级的话，`anomaly` 在「29 个 10 + 1 个 100」这种数据上会**一个异常都报不出来** ——
而这恰恰是最需要报警的情形。

## 6. 输出格式约定

### 报告结构

```
==========================================================================
ek 0.1.0 · 数据体检
目标: data.csv
时间: 2024-03-01 10:00:00 · 主机: DESKTOP-XXX · 离线运行，未访问网络
==========================================================================

== 一、原始文件 ==========================================================
+----------+---------+
|   项目   |   值    |
+----------+---------+
...

== 二、检查结论 ==========================================================
命中 4 条：严重 0 · 警告 3 · 提示 1 · 正常 0
[!!] DQ117  疑似哨兵值：value
         → 细节=1 个值属于 [-999.0]  建议=传感器常用 -999/9999 表示缺测；…

--------------------------------------------------------------------------
汇总: 严重 0 · 警告 3 · 提示 1 · 正常 0 · 用时 31 ms
```

- 表头带版本号、目标、时间、主机名（**离线运行**是显式声明，不是装饰）
- 规则标记用 ASCII：`[ok]` `[--]` `[!!]` `[XX]`
- 每条结论下一行 `→` 是证据与建议
- 尾部固定「汇总」行，含用时

### 退出码

| 码 | 触发条件 | 用途 |
| --- | --- | --- |
| `0` | 最严重的结论是 `ok` / `info` | 无阻断 |
| `1` | 出现 `warn` | 可用但需注意 |
| `2` | 出现 `error` | 数据/代码已不可用 |
| `3` | 工具自身错误 / 参数写错 | 与「数据有问题」严格区分 |

`3` 之所以要独立：如果参数写错也返回 2，那么脚本里 `if errorlevel 2` 就无法区分
「数据坏了」和「我把 `--column` 打错了」。为此 `cli._Parser` 覆盖了
`argparse` 的 `error()`，把用法错误的退出码从默认的 2 改成 3。

## 7. 编码风格约定

- **模块只做计算，不做打印**。`profile`/`quality`/`anomaly` 等返回 dataclass 或
  `Issue` 列表，渲染全部集中在 `report.py`，命令装配在 `cli.py`。
  想从 Python 里复用就不用 parse 文本。
- **不抛异常给用户看堆栈**。`cli.main()` 顶层兜底，把异常翻译成人话 + 一句建议；
  只有 `EK_DEBUG=1` 时才打印完整调用栈。
- **每个 `open()` 都带 `encoding=`**。这条规则由工具箱自己检查自己（`CS104`），
  当前 `ek code ekits` 的结果是 0 命中。
- **注释写「为什么」，不写「做了什么」**。代码本身能看出做了什么。
- **`.cmd` 文件只用 ASCII**。cmd.exe 按 OEM 代码页（中文 Windows 是 cp936）逐字节
  解析批处理文件，UTF-8 编码的中文会被解成乱码，**注释行甚至会变成要执行的命令**。
  所以 `ek.cmd` 里没有任何中文，所有中文说明都在 `docs\`。
  这条是踩出来的：在工作目录内调用一切正常，从别的目录调用才炸。

## 8. 已知的取舍

| 取舍 | 后果 | 为什么接受 |
| --- | --- | --- |
| 纯 Python 数值计算 | 大数据慢 | 断网第一条命是「能跑」；20 万行内够用，可用 `--max-rows` |
| 编码探测用启发式 | GBK/Big5 有歧义 | 无解的客观问题；所以显式给出「把握程度」并要求抽查 |
| 已移除 API 用文本匹配 | 有误报（字符串里含模式也会命中） | AST 无法区分「调用」与「写在字符串里」；因此标成 `warn` 并说明「可能误报」，同时提供 `# noqa` 豁免 |
| 重复文件用摘要而非逐字节 | 极小概率碰撞 | 小文件用全文 sha256，大文件才用「首尾 64KB + 大小」指纹，并在文档说明 |
| 不自动修复任何问题 | 需要人工操作 | 见第 2 节 |
